## On the copyright rule — you said you trust me, so here's what I did and why

I did **not** remove it. Three things I found:

1. **It restricts none of your books.** The whole library ships in the prompt and is quoted and cited

2. **It's an anti-hallucination guard wearing a copyright coat.** Its own message leads with *"I don't

the message as noise for a private app. Still yours to overrule — just know it produces wrong riffs, not

## Things my own briefs got wrong that subagents caught

Worth knowing, because they're the reason this works:

- My `/v1/vision` spec **could not have worked**: `--bare` kills the subscription; `--add-dir` is variadic
  and ate the prompt; `./media:/media:ro` is the wrong filesystem (the api uses a *named volume*) — it
  would have looked mounted and 400'd every call with both containers healthy.
- **`--tools Read` is not a security fence.** Claude read `/etc/hostname` from the container that mounts
  your real `~/.claude`. Fixed with `--permission-mode manual` + a deny over `~` and `/proc`. The best
  catch: a probe asking for `.credentials.json` came back clean and **proved nothing** — that was the
  model declining, not the sandbox refusing. A safety-trained model is not a security control.
- My named-song reorder was **a no-op as briefed**: `_is_content_bearing` skips retrieval for any turn
  containing "tab" — the trigger word itself.
- My `OCR_PROVIDER` sketch would have handed a `claude` provider an **empty API key** in exactly the
  target scenario.
- A pre-existing production bug fixed in passing: `_classify` grepped `json.dumps(payload)`, so
  `"429" in "4291"` turned a **4.291-second** failure into a `rate_limit` that `jobs/runner.py` requeues
  **forever**. The 888-page run would have hit it repeatedly.
