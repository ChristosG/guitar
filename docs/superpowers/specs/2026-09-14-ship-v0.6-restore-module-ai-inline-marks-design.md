# Ship v0.6: a restore that cannot depend on the database's past, a visible AI door on the module, and bold/italic/underline in the tutor's text

**Date:** 2026-09-14 · **Branch:** `desktop` · **Status:** approved by Chris's brief of 2026-09-14 21:34 ("we are ready to ship for good this time")

## 0. What triggered this

1. The tutor's Mac (desktop-v0.5.2) could not restore the webapp archive that Chris's Linux .deb restored fine. His logs are not in hand yet. Extending the bundle smoke test with a backup round trip reproduced a REAL restore failure on the identical v0.5.2 tree: restoring the bundled seed (schema `c7d8e9f0a1b2`) into a database that `alembic upgrade head` had built dies inside `pg_restore --clean`:

   ```
   cannot drop constraint page_pkey on table public.page because other objects depend on it
   DETAIL: constraint fk_chunk_page_id on table public.chunk depends on index public.page_pkey
   ```

   Root cause: `--clean` emits a DROP for every object **in the dump**, and nothing else. The webapp's database names the chunk→page foreign key `chunk_page_id_fkey` (every dump cut from it carries that name); a database built by the migrations names it `fk_chunk_page_id` (`alembic/versions/f73763fd9f1e_library_pages_collections.py:59`). Whenever the live database holds a dependent object under a name the dump does not know, the DROP of the parent's primary key fails and `--exit-on-error` aborts the restore with the tables half-dropped. That is a restore whose success depends on the *history* of the target database — precisely the property a backup must not have. (Chris's .deb had been seeded from the webapp-named dump, so its names matched; a fresh install whose seed was skipped or interrupted, or any future release whose migrations add a constraint, hits it.)

2. Chris: the module row («Η Κιθάρα ως Πηγή του Ήχου» is a *module*) shows the tier chip «Η βιβλιοθήκη σου», which tells the tutor nothing, while the only AI door on a module is hidden inside the ⋯ menu.

3. The tutor asked for bold / italic / underline on his text.

## 1. Restore: replace the schema, never negotiate with it

`POST /backup/restore` (apps/api/app/routers/backup.py) after validation:

1. `db.rollback()` (as today), then in **one** statement through the request's session: `DROP SCHEMA public CASCADE; CREATE SCHEMA public; GRANT ALL ON SCHEMA public TO public;` and `db.commit()`. Proven 2026-09-14 against `pgvector/pgvector:pg16`: the CASCADE takes the `vector` extension with it (`pg_extension` count 0 afterwards) and the dump's own `CREATE EXTENSION vector` puts it back; the seed dump then restores with exit 0 into a database that had the migration-named constraint.
2. `pg_restore --no-owner --no-privileges --exit-on-error <conn> db.dump` — **no `--clean`, no `--if-exists`**. The schema is empty; there is nothing to clean.
3. `alembic upgrade head` as today (skipped when the dump has no `alembic_version`).
4. Media swap and superseded put-back as today.
5. `engine.dispose()` (apps/api/app/db.py) — every pooled connection saw the old `vector` type OID; the next request must open fresh ones. Wrapped in try/except: a dispose failure must not fail a restore that already happened.

The docstrings (module + `restore_backup`) say why `--clean` is gone. `tests/test_backup_api.py` pins the new argv and adds a real round trip in which a constraint is renamed to a name the dump does not know before the restore (the exact CI failure) — with `--clean` it would fail, with the schema reset it passes.

Also: the upload is opened with `tarfile.open(path, "r:*")`, so a plain `.tar` (what Safari's "open safe files" leaves behind after it auto-decompresses a download) restores too; the picker accepts `.gz,.tgz,.tar,application/gzip,application/x-tar`.

The Settings card shows the server's `message` under the Greek sentence when a restore fails (small, muted, `data-testid="backup-error-detail"`) — so the next screenshot from the Mac carries the cause instead of only «Η επαναφορά απέτυχε».

The bundle smoke (`desktop/scripts/smoke.sh`, already edited) exports, restores its own export, then restores the bundled seed and checks curricula count and media file count. It runs on BOTH CI runners against the tree that ships, so the macOS restore path is proven on every build even though nobody here has a Mac.

## 3. Bold / italic / underline

### Storage
Inline markers in `Block.body`, exactly three: `**bold**`, `*italic*`, `<u>underline</u>`. Nesting allowed (`**bold *and italic***`, `<u>**x**</u>`). No other Markdown is interpreted. Verified 2026-09-14: no segment body in the live database contains `**`, `<u>`, a heading or a list marker, so there is no legacy text to reinterpret. `<u>` rather than an invented `++`: the models already know what `<u>` means, so "preserve the markers" costs one sentence.

### One grammar, two implementations, one test table
- `apps/web/src/lib/inline-marks.ts`: `parseInlineMarks(text): InlineNode[]` (`{type:"text",value}` | `{type:"strong"|"em"|"u", children}`), tolerant: an unclosed marker is literal text; `toggleMark(text, start, end, mark): {text, start, end}` for the editor (wraps the selection; if the selection is already exactly wrapped — inside or outside the markers — unwraps; an empty selection wraps the word around the caret, or inserts an empty pair with the caret inside when there is no word); `stripInlineMarks(text)`.
- `apps/api/app/curriculum/inline_marks.py`: the same `parse_inline_marks(text)` producing the same tree, plus `strip_inline_marks(text)`.
- Both are checked against the SAME cases (a JSON table `apps/api/tests/fixtures/inline_marks_cases.json` = `apps/web/tests/fixtures/inline_marks_cases.json`, byte-identical, each side's test loads its copy; a test on the API side asserts the two files are identical).

### Rendering
- `components/ui/inline-marks.tsx`: `<InlineMarks text=… />` renders the tree as `<strong>`, `<em>`, `<u>` inside the existing `whitespace-pre-wrap` paragraph. Used for the block body display in `block-card.tsx` (segment, lesson, module, course bodies). The «Τι άλλαξε» diff views keep plain text (a word-level diff cannot carry spans across runs) but `prose-diff.ts::fold` strips the markers, so bolding a word is not reported as a rewrite.
- `export_docx.py`: segment/lesson/module/course paragraphs are built from the tree as runs with `bold`/`italic`/`underline`, so the Word export shows formatting instead of asterisks.
- `depth.count_words` strips the markers before counting (a `<u>` tag counted as the word "u" twice).

### Editing
In the body editor (`block-card.tsx`, the `editingBody` form):
- A small toolbar above the textarea: three ghost buttons **B** / *I* / <u>U</u> (`data-testid="mark-bold|mark-italic|mark-underline"`, `aria-label` el «Έντονα» / «Πλάγια» / «Υπογράμμιση», en Bold / Italic / Underline). `onMouseDown` calls `preventDefault()` so the textarea keeps focus and its selection; onClick applies `toggleMark` to the current selection and restores the selection.
- Keyboard: Ctrl/⌘+B, Ctrl/⌘+I, Ctrl/⌘+U inside the textarea do the same.
- **Autosave**: 1500 ms after the last keystroke, and immediately on blur, the draft is PATCHed if it differs from the last saved value — through a quiet path that does NOT flip `busy` (the textarea must never be disabled mid-typing). A status line beside the buttons reads «Αποθήκευση…» while a save is in flight and «Αποθηκεύτηκε» after; an error keeps the existing red line. «Αποθήκευση» (the existing `body-edit-save` button) flushes and closes; «Ακύρωση»/Escape closes and, if anything was autosaved during this edit, PATCHes the text that was there when the edit started (a cancel still means "as it was"). Toolbar clicks never blur, so they never trigger a save by themselves.
- Chris floated putting the three buttons in the top bar next to Settings. Decision: they live above the text they act on. A global bar would be dead on every screen but one and far from the selection it formats; if he prefers the top bar after trying it, the toggle function is shared and moving the buttons is a 20-line change.

### The models
One sentence appended to `CURRICULUM_STYLE` (`app/i18n.py`), after the citations bullet:
`- INLINE MARKERS: text you are given may carry **bold**, *italic* or <u>underline</u> markers around words; keep them exactly where they are in any text you keep or lightly edit, and do not add markers of your own.`
This changes 9 registry entries × 2 locales in the byte-identity baseline; the baseline is regenerated only after the diff is confirmed to be exactly those (`python -m tests.prompt_baseline`).
